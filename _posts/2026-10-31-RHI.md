RHI：Recursive Harness Self-Improvement

<div id="toc-slot"></div>

## 问题：Provider 的 Harness 太贵，用户的 Harness 太难

Coding Agent 的竞争已经从「谁的模型更强」扩展到「谁的执行框架更高效」。同一个模型，由谁拆任务、子 Agent 之间交换什么信息、工作流按什么顺序推进，都会影响最终结果。

但这里有个结构性矛盾：

- **Provider 内置的 Harness 必须泛化到所有用户和任务**，很难针对具体项目精细调整，持续更新成本也极高。
- **用户自己写的 Harness 可以专门化**，但缺乏轻量、可持续的优化手段。现有方法通常依赖基于种群的搜索——生成大量候选、并行执行和评估，计算开销巨大，不适合在日常开放任务上持续优化。

所以 RHI 的核心问题很直接：**在固定模型的前提下，能否用极少的迭代次数和计算开销，持续改进用户构建的 Harness？**

## 方法：不搜候选池，只和上一轮比
RHI 的设计哲学是**极简递归**——不维护候选池，不并行评估，每轮只做一件事：把当前 Harness 和上一轮的输出做对比，用反馈驱动下一轮修改。

### Harness 即 Prompt
把 Harness 表示成 Agent loop 的 prompt 级规范，而不是可执行代码。这样修改可以直接在文本层面完成：不需要编译、不需要调试、不需要重新部署。

### 轨迹局部自比较
每轮只把当前 Harness 与直接前驱比较，只需要 1 次 Agent 执行 + 1 次成对评估，把每轮成本降到 **Θ(1)**。传统种群搜索需要 Θ(m²) 级别的成对评估，RHI 直接砍掉一个数量级。

| 搜索目标 | 成本 |
|---|---|
| 在种群 M 上求理想目标 | Θ(M²) |
| 有限种群搜索（m 个候选） | Θ(m²) |
| **轨迹局部 RHI** | **Θ(1)** |

### 基于自比较历史的动量信号
通过累积历史偏好反馈指导 Harness 修订，避免单步噪声误导。这有点像优化器里的动量项——不是每一步都听最新的梯度，而是看趋势。

*每轮只产生一次执行和一次成对判断；历史偏好构成动量信号，与候选池大小无关。*

### 隐式优化目标：信息论解释
论文最后给了一个形式化解释：RHI 的隐式更新目标可以理解为——**最大化每个组件与任务之间的互信息，同时惩罚组件之间的冗余**。

换句话说，RHI 不是让 Harness 变得更长更复杂，而是让每个组件更针对当前任务、组件之间少重复。这也解释了为什么性能提升的同时，token 消耗反而下降。

<img src="/images/2026-10-31-RHI/fig3-attribution.webp" alt="收益来自信息流组织" title="归因" width="864" height="435" loading="lazy" decoding="async">

*论文的归因：收益主要来自角色、指令、上下文、交互跳数之间的信息流变干净，而不是让模型想得更久。*

## 效果：低推理档超过高推理档，成本还降了
论文在 30 项开放式机器学习研究任务上验证，覆盖量化金融、机器人和药学，使用 Claude Sonnet 和 Opus 系列模型。

结论是：**几个 RHI 迭代，就能把低推理档 Agent 的性能上限抬到超过对应的最高推理档，同时把推理成本大幅压低**——最高降幅达 60%。

以 Opus-4.8 为例：

| 对照 | 成本变化 | 缓存读写 |
|---|---|---|
| vs `opus-4.8-max`（2.19） | 1.69，**-23%** | 2.51 → 1.69，**-32%** |
| vs `opus-4.8-ultracode`（4.15） | **-60%** | 4.74 → 1.69，**-64%** |

更关键的是，输出 token 数量基本稳定——说明收益不是来自「让模型想得更久」，而是来自「让模型想得更对」。

<img src="/images/2026-10-31-RHI/fig2-effort.webp" alt="低推理档 + RHI 反超最高档" title="成本与效果" width="937" height="490" loading="lazy" decoding="async">

*左图为示意：低推理档加几轮 RHI 后越过最高档基线；右图为论文中 Opus-4.8 的归一化成本。*

归因分析把收益拆成三条：

1. **通信契约增强**：子 Agent 之间的信息交换更针对具体任务
2. **工作流与任务的信息关联增强**：每步做什么、为什么做，和当前任务更相关
3. **组件之间的冗余减少**：重复劳动变少

## 代价和局限
- **Harness 表达能力受限于文本**。「Harness 即 Prompt」换来了低成本，但也意味着无法表达需要真实代码实现的能力（例如新的工具运行时）。
- **依赖成对判断的质量**。RHI 每轮只比较两个版本，如果评判者本身不稳定，动量信号会把噪声放大成趋势。
- **任务域较窄**。30 项任务都在合成 ML 研究场景，真实工程项目里的工具链、依赖、权限复杂度要高得多。
- **多轮稳定性未充分验证**。论文展示的是少数几轮迭代的收益，长期递归是否仍单调，还没有答案。

## 本质：把「改 harness」从搜索问题变成对比问题
RHI 的贡献不是发明了新算法，而是换了一个成本模型：与其在一个巨大的离散空间里做种群搜索，不如把每轮更新变成一次「A 和 B 哪个更好」的判断，再用历史偏好平滑掉噪声。

这和另外两条路线形成对照：ModularRSI 靠拆模块降低搜索维度，RRSI 靠正则化约束搜索轨迹，RHI 则是**把每轮成本压到常数**。三条路都在回答同一个问题——在不改权重的前提下，如何让 harness 越用越好，而不是越用越贵。

一句话总结：**RHI 把「改 harness」从搜索问题，降级成了对比问题。**
