RRSI：Regularized Recursive Self-Improvement of Agent Harnesses

<div id="toc-slot"></div>

## 问题：自我改进最大的敌人不是「不聪明」，而是「太会应试」

Agent Harness 的自我改进已被证明有效：不改权重，只改 prompt、工具、控制流、记忆这些「外壳」，就能让同一个模型在特定任务上持续涨分。

但这里藏着致命陷阱：**Harness 反复在同一组任务上迭代，分数越改越高，换一套新任务就掉回去。**

论文把这种现象拆成三种形态：

- **背题目**：把任务名、答案、基准特定逻辑直接写进流程
- **追噪声**：评测本身有随机波动，系统把偶然的正向波动当成真实提升
- **堆复杂度**：不加区分地叠组件，token 越烧越多，新增部分对泛化没有贡献

所以 RRSI 的核心问题是：**怎么让自我改进的收益迁移到未见过的新任务，同时不让算力和 token 无节制膨胀？**

<img src="/images/2026-10-31-RRSI/fig1-overfit.webp" alt="三种应试形态" title="三种过拟合" width="967" height="447" loading="eager" decoding="async">

*三种形态在训练分布上都表现为「进步」，换到分布外就一起消失。*

## 方法：不限制「改什么」，限制「怎么改」
RRSI 的设计哲学是——**约束搜索轨迹，而不是约束可编辑空间**。prompt、工具、控制流、记忆，什么都可以改；约束放在提案端和选择端，控制搜索过程本身。

### 提案端：三道约束控节奏
1. **退火编辑预算**：早期允许一次打包多个改动，探索空间大；随迭代推进，逐步压到一次只能改一处。这样后期每次提升都能归因到具体改动。
2. **历史记录约束**：成功和失败的历史都参与归因。已被否定的假设不会反复消耗候选预算，避免钻牛角尖。
3. **停滞探索**：进展停滞时，搜索自动转向尚未充分探索的组件，防止卡在局部最优。

### 选择端：四道门筛方案
1. **泄漏筛查**：先排除把题目名、答案、基准逻辑写进流程的候选——最粗暴也最有效的防背题手段。
2. **噪声门槛**：用基础 Harness 的重复评测估计噪声带，候选提升必须显著超过噪声。
3. **复杂度验收**：额外的策略 token 必须有对应提升来证明其合理性。
4. **结构剪枝**：最近几轮没贡献的组件会被建议删除。

*左边控制候选怎么生成，右边控制候选能不能上位；两端缺一不可，消融会证明这一点。*

### 实验设置
主实验冻结 Claude Opus 4.8，在 Harvey LAB（法律办公任务）上做演化，再迁移到三套完全没参与演化的基准：**JobBench**（通用办公）、**GDPval**（经济学任务）、**APEX-Agents**（多领域综合）。对照方法包括 Meta-Harness、AHE、TTHE、HarnessX 等。

## 效果：少拿熟题分，多赚新题分
### 分布外迁移：所有指标都为正
| 基准 | 无演化基线 | RRSI | 对比方法最好成绩 |
|---|---|---|---|
| Harvey LAB（演化集） | 89.4 | **90.5** | 93.0（Meta-Harness） |
| JobBench | 36.0 | **40.7** | 37.2（AHE） |
| GDPval | 48.8 | **52.3** | 49.1（Meta-Harness） |
| APEX-Agents | 34.2 | **37.9** | 35.7（Meta-Harness） |

注意第一行：RRSI 在演化集上**故意**比无正则演化低（90.5 vs 92.8），这是它主动做的交易——放弃一部分熟题分，换分布外的泛化。OOD 平均 43.6 vs 无正则的 40.3，高出 3.3 分。

<img src="/images/2026-10-31-RRSI/fig3-results.webp" alt="ID 与 OOD 的取舍" title="主结果" width="880" height="475" loading="lazy" decoding="async">

*左：演化集上让出分数；右：分布外平均反超。这正是正则化想要的方向。*

### Token 效率：比无约束省 36%
| 设置 | 每次 trial 的策略 token |
|---|---|
| 初始 Harness | 1.56M |
| 无正则演化 | 3.80M |
| **RRSI** | **2.42M（↓36%）** |

RRSI 仍有额外开销，但比无约束的「野蛮生长」省了一大截——约束不是拖慢搜索，而是砍掉无效复杂度。

<img src="/images/2026-10-31-RRSI/fig4-tokens.webp" alt="token 成本" title="成本" width="915" height="396" loading="lazy" decoding="async">

*正则化在 token 上是「回本」的：比无约束省 36%，同时分布外分数更高。*

### 消融：两端都不可少
| 变体 | OOD 平均 |
|---|---|
| 去掉提案端约束 | 41.9 |
| 去掉选择端约束 | 41.0 |
| **完整 RRSI** | **43.6** |

两端缺一不可，选择端贡献略大。

## 代价和局限
- **权重全程冻结**。RRSI 只优化 Harness，不涉及模型后训练；如果基础模型本身有结构性缺陷，Harness 修修补补效果有限。
- **评判依赖闭源模型**。搜索、分析和批评都依赖闭源模型，完整复现需要多套基准、容器环境和大量 API 预算。
- **跨模型迁移能力弱**。用 Gemini 3.5 Flash 搜得的 Harness 迁移到 Gemini 3.1 Flash Lite，Terminal-Bench 2.1 从 11.2 升到 14.6——相对提升 30.4%，但绝对分仍很低。Harness 高度依赖底座模型的能力边界。
- **统计显著性未充分报告**。主结果没有给出多次独立进化的方差检验，单轮演化的偶然性无法完全排除。
- **长时程演化未验证**。如果持续自我改进几十轮、上百轮，约束是否仍然有效，仍是开放问题。

## 本质：把「正则化」从权重训练搬到系统进化
RRSI 的价值不在于发明了新的自我改进方法，而在于**第一次系统性地把机器学习的正则化思想平移到了 Harness 的搜索过程**。

传统 RL 里的正则化防止权重过拟合训练数据；RRSI 的正则化防止 Harness 过拟合评测基准。数学对象不同，但本质是同一个问题：**如何在有限反馈下追求真实泛化，而不是追求指标最大化？**

对做 Agent 的人，三条实用启示：

1. **涨分不等于变强**——任何自我改进系统都必须用「未见过的新任务」做最终检验，否则就是自欺。
2. **约束比自由更有效**——给系统「想改什么就改什么」的自由，不如给「怎么改」加护栏。
3. **精简即泛化**——被剪掉的组件不是浪费，而是防止系统靠堆复杂度刷分。

一句话总结：**让 AI 自己改进自己，最大的陷阱不是它不够聪明，而是它太会应试。**
